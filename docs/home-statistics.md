# Статистика Главной

`GET /api/home/statistics?period=today` — только чтение, один согласованный
снимок PostgreSQL (`REPEATABLE READ READ ONLY`), `Cache-Control: no-store`.
Без period или с пустым period используется today. Неизвестный период либо
повторение period возвращает HTTP 400. Ошибка БД — HTTP 500, без ложных нулей.

## Период

Часовой пояс сайта — Asia/Krasnoyarsk (UTC+07:00).
today начинается сегодня в 00:00; 7d — в 00:00 шесть дней назад;
30d — в 00:00 двадцать девять дней назад. Верхняя граница — момент запроса,
не включительно. Это календарные периоды, включающие текущий день.

## Доступные показатели

- receiving.sessions: завершённые сессии по completed_at внутри периода.
  Скрытая история (deleted_at) не отменяет факта проведённой приёмки.
- receiving.placedQuantity: сумма receiving_placement_items.quantity для
  действующих размещений по receiving_placements.created_at за период.
  Отменённые размещения исключаются; размещение незавершённой сессии учитывается.
- receiving.pendingQuantity: текущее количество receiving_session_items
  всех сессий status=active, независимо от периода.
- stock.totalQuantity: весь cell_stock, включая архивные товары.
- stock.occupiedCells: число уникальных ячеек с положительным остатком.
- stock.totalCells: все существующие ячейки.
- stock.skuCount: число SKU с положительным суммарным остатком, включая архивные.
- stock.lowStockCount / lowStockItems: SKU с суммарным остатком 1–5 включительно,
  включая архивные. Ноль исключён. Сортировка: quantity, затем sku.
- assembly.queuedOrders: ozon-заказы status=queued с импортированной текущей
  версией в assembly_order_heads, как в GET /api/assembly/orders.
- assembly.activeOrders: ozon-заказы status=in_progress.
- assembly.problemOrders: число разных ozon-заказов, для которых создана
  проблема в периоде (assembly_problem_records.created_at). Несколько проблем
  одного заказа считаются один раз. Разрешённые/возвращённые также учитываются:
  это история возникновения проблем, а не текущее число открытых проблем.

Все поля stock, pendingQuantity, queuedOrders и activeOrders не зависят от периода.
Исторические preview-заказы исключены из статистики реальной сборки.

## Недоступные показатели — JSON null

- receiving.receivedQuantity: нет полного журнала принятых количеств с датами.
  Остаток receiving_session_items изменяется, очищается размещением и удалением;
  receiving_quantity_requests покрывает лишь часть путей изменения количества.
  Сумма размещённого и ожидающего не восстанавливает поступление за период.
- assembly.completedOrders: status=completed хранит текущее состояние, но в
  общей модели заказа нет надёжного времени завершения. created_at — создание
  записи заказа, recorded_at версии — сохранение состава; это не дата сборки.
- assembly.averageAssemblySeconds: нет общего журнала начала и завершения
  сборки, в том числе повторных попыток. Первый/последний отбор не равнозначен
  началу/завершению сборки. Request receipts и события отдельных проблем
  не дают полного доменного журнала для всех заказов.

Эти три поля всегда null, включая пустую БД: ноль означал бы подтверждённое
отсутствие операций. Миграции и изменения бизнес-процессов для их сбора в этой
задаче не добавляются. История последних действий в этот endpoint не входит.
