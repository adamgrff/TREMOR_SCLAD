# История главной страницы

`GET /api/home/history?limit=20` возвращает `{ "events": [...] }`.
`limit` — целое число от 1 до 100, по умолчанию 20; неверные значения и повтор параметра возвращают 400.
Период статистики не применяется к истории. Порядок: `occurredAt DESC`, затем стабильный `id DESC` при одинаковом времени.
Один SQL-запрос читает все источники в едином снимке БД. При ошибке БД endpoint возвращает 500, без подмены пустой историей.

Поля события: `id`, `occurredAt` (RFC3339), `process`, `event`, `description`, `references`.
Ссылка содержит `type` (`sku`, `cell`, `order`) и исходное `value` без префиксов отображения.
ID включает название источника и его первичный ключ; одинаковые числовые ключи разных журналов не пересекаются.

## Источники

- `receiving_intake_events`: каждое фактическое добавление товара, его количество, SKU и время `occurred_at`.
- `receiving_placements` + `receiving_placement_items`: одна строка на размещение, сумма количества, все SKU и ячейка. Время — `created_at`. Отменённое размещение остаётся историческим фактом с пометкой «размещение отменено»; это не текущее состояние остатков.
- `assembly_lifecycle_events`: начало и успешное завершение сборки реального заказа (`source=ozon`), время `occurred_at`.
- `assembly_problem_records`: факт перевода реального заказа в проблемные, исходное `created_at` и причина `problem_type`. Решённая проблема не удаляется из истории. Данные preview исключены.
- `assembly_ozon_observations` + `assembly_ozon_operations`: только записанные результаты `applied`, `rejected`, `cancelled`, время `observed_at`, ссылка на заказ. Запрос операции, недоступность клиента и неопределённый ответ не доказывают её успех. Эти строки не называются синхронизацией.

Отдельные сканы, резервирование, подбор и возвраты сборки не становятся строками этой истории.
Надёжного самостоятельного журнала перемещений между ячейками нет: события `cells` не синтезируются.
Официальной синхронизации Ozon и журнала её завершения нет: события «Синхронизация завершена» не создаются.
При отсутствии подтверждённых Ozon-наблюдений раздел истории не показывает Ozon-событий.
История ограничена существующими записями: старые факты до появления журналов приёмки и lifecycle не восстанавливаются.
Необходимы ранее добавленные миграции 020 и 021; новых миграций для endpoint нет.
Связанные SKU и коды ячеек читаются из текущих справочников, а не из исторических снимков названий.

## Frontend

История запрашивается при открытии окна независимо от периода статистики, `cache: no-store`.
Загрузка, отсутствие событий и ошибка имеют отдельные состояния без демонстрационных данных.
Сортировка учитывает полную дату, а не только часы; время показывается в `Asia/Krasnoyarsk`.
Существующие process-pill и copy-pill сохранены: копируется отображаемое значение с префиксом `№` / `SKU`.

Проверки: `TestHomeHistory*` на PostgreSQL и `frontend/scripts/test-home-history.mjs`.
