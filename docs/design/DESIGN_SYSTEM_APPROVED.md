Первая волна: рабочие области Приёмки (списки/история/каталог), Очередь, Активная сборка, Проблемные и Архив проблем, только тёмная тема. ## 8. Event History Popover

Это специализированный существующий паттерн истории, не Error Tooltip, Badge, Counter или универсальный Popover.

Алгоритм groupProblemHistory сохраняется: ключ включает kind, operationId, title, message, outcome; внутри группы события идут по возрастанию createdAt. Последнее событие показывается в основной истории, previous содержит предыдущие; +N = previous.length. Все тексты, даты, секунды и зона Asia/Krasnoyarsk, режим «Показать все события» и существующие технические сведения доступны без потерь.

Подписи образца: «1 · Ячейка», «2 · Товар», «3 · Отправление». Элементы не являются кнопками. Ширина по тексту, без равных фиксированных сегментов. При узкой рабочей колонке допускается локальная прокрутка строки без уменьшения текста, разрыва подписи и изменения grid страницы; сохраняются keyboard-доступ к переполненной области и фокус сканера.

Карта данных: step=cell — первая стадия active; step=product — первая completed, вторая active; step=shipment — первые две completed, третья active. shipmentConfirmed=true даёт три completed, без нового четвёртого этапа. Если заказ ещё требует других ячеек, текущая логика возвращает step к cell: отображается новый цикл, а не ложное завершение всех ячеек заказа. При отсутствии заказа строки нет. Ошибка/blocked не продвигает этап; тот же step не запускает анимацию на каждом скане. Undo и восстановление отображаются из реальных данных, без локального анимационного счётчика.

Переход: предыдущий контур и текст сереют150ms; arrow→dot crossfade150ms в том же slot; следующий синий контур обрисовывается300ms по периметру; его текст становится белым150ms. Процессы параллельны, общая длительность300ms, easeOut. Старый контур остаётся серым, не стирается. Нет пульсации, glow, блокировки сканера и очереди устаревших анимаций. Первый показ и восстановление сразу отражают фактическое состояние; reduced motion0ms.

Приёмке не навязывать строгий цикл поверх свободного набора группы. ReceivingScrollProgress остаётся навигацией. Статус «Сканирование АКТИВНО / Приёмка ЗАВЕРШЕНА» действительно меняется по isFinished: не считать его всегда статичным декором, не удалять и не делать обязательным общим компонентом. Существующий код ожидаемой ячейки также сохраняется локально до отдельного решения.

Таймер ожидания в Очереди — отдельная метрика возраста заказа. Расчёт сохраняется: max(0,floor((now−createdAt)/60000)); clock обновляется каждую секунду и при visibilitychange. Пороги не меняются.

## 11. Границы реализации и проверки

Утверждение канона не разрешает новый DataTable/универсальный Popover, новый Ozon workflow, пагинацию непостраничных списков, API total, новый combobox, новые стадии сканирования, глобальный font/reset или массовую очистку CSS. Утверждённые UI-изменения modal Escape/focus, keyboard/позиционирования истории и Step display реализованы в I8–I10. Последующие изменения поведения требуют отдельного этапа без изменения предметной логики/API.

Каждый этап: малый diff и визуальное принятие; скриншоты одинаковых данных, zoom и браузера; scoped-изменения; неизменность светлой темы и исключений; long/wrap/disabled/loading/focus; функциональные регрессии существующих сценариев. Baseline снимается от актуальной локальной копии, не GitHub main. Коммиты и push — только по отдельному разрешению; старое общее указание о коммитах на каждом этапе не отменяет текущий запрет.

Реестр значений: TOKENS.v1.json. Компоненты: COMPONENTS.md. Исключения: EXCEPTIONS.md. Ограничения и разделение visual/behavior/API: DECISIONS.md. Конкретный план: IMPLEMENTATION_PLAN.md. Неурегулированное локальное свойство не получает новый «финальный» токен по аналогии: сохранить текущий вариант и отдельно согласовать при разрешённом подключении.
