# TREMOR SCLAD: основа дизайн-системы

Срез: 16 октября 2026. Исходная точка: тег `demo-design-system`, коммит `85d42bc`.
Система фиксирует существующий интерфейс. Выбор эталона не разрешает менять уже
утверждённые страницы. Статус Разбора — текущий черновик, а не утверждённый общий канон.

## Файлы и область подключения

- `frontend/src/styles/tokens.css`: реестр значений с префиксом `--ui-`.
- `frontend/src/styles/ui.css`: подключает токены; только явно выбранные классы,
  без reset, глобальных селекторов элементов, загрузки шрифтов или смены темы.
- Подключение только из `Disassembly.tsx`, перед его локальным CSS.
  Другие страницы не переведены на эти классы. Даже если сборщик загрузил CSS
  для всего маршрута, старые классы он не переопределяет.
- Рабочий шрифт наследуется от существующего контейнера. `Noto Sans` указан в
  стеке, но не поставляется проектом: фактический fallback зависит от окружения.
- Существующий `--site-scale: .7` не переносится и не пересчитывается.
  Размеры ниже — CSS px до zoom. Не менять zoom ради унификации.

## Как выбирать оформление

1. Определить визуальную роль и семейство: фирменное или рабочее.
2. Найти существующий эталон в таблицах ниже и выбрать точный вариант.
3. Использовать реализованный класс только при совпадении всех нужных свойств
   и состояний. Отсутствующий вариант не заменять похожим.
4. Геометрия страницы, сетка, ширины колонок, отступы между областями, sticky,
   прокрутка и адаптивность остаются локальными.
5. Черновой элемент остаётся локальным до отдельного утверждения. Схожесть
   оттенка или назначения не является основанием выравнивать значения.

Фирменное семейство: Главная, Header, навигация Ячеек, схема стеллажа.
Palui/Bauhaus, uppercase, свечение и прозрачные поверхности сохраняются.
Рабочее: Приёмка, Очередь, Активная сборка, Проблемные, Разбор и окна Ячеек.
Стек `Noto Sans, Arial, sans-serif`; тёмные панели остаются тёмными и в светлой теме.

## Подключение Разбора

Переведены только четыре точных эталона:

- `receivingPage__panel` → `ui-panel`;
- `receivingPage__panelTitle` → `ui-section-title` (только h2 «РАЗБОР»);
- `assemblyQueue__subtitle` → `ui-section-description`;
- `receivingHistory__button` → `ui-button`, включая hover/focus/disabled.

Остальные селекторы `disassembly*` сохраняются. В том числе: сетка 3:2,
размеры/отступы, очереди и таблицы, статусы, метрики, поле сканирования,
целевая ячейка, progress, галочки, анимация шагов, ошибка #efa3a3 и финальные
переопределения helper-текста 18px/#9a9a9a/400/1.4. Не переносить ранние
перекрытые значения CSS вместо итоговых. Backend и обработчики не меняются.
`ui-section-description` сохраняет также `flex-shrink: 0` исходного
`assemblyQueue__subtitle`, заданный отдельно от его основных свойств.

## Проверки

Из frontend: `npm test`, `npm run lint`, `npm run build`.
Визуальная регрессия: `node scripts/check-design-system-visual.mjs`.
Нужен установленный Playwright (переменная `PLAYWRIGHT_MODULE` — абсолютный
путь к его `index.mjs`); `BROWSER_EXECUTABLE` опционально задаёт Chromium/Edge.
Пакеты проекта и lockfile для проверки не изменяются.

Скрипт сравнивает с тегом `demo-design-system` SSR-разметку реального компонента
в Chromium: pixels и computed styles всех элементов, 1920/1000/390px,
dark/light, empty/waiting/paused/product/cell/error/blocked/complete,
hover и focus кнопок. Артефакты по умолчанию вне репозитория, в
`TREMOR/checkpoints/design-system-visual/`; можно задать `VISUAL_OUTPUT`.
Фикстуры не обращаются к API и не меняют складские данные. Проверка покрывает
отображение компонента и CSS; не заменяет проверку живого складского сценария
или анимации перехода между шагами. Анимации отключены для сравнения кадров.
Для нестабильного кадра допускаются до трёх повторных снимков без изменения
CSS; устойчивое несовпадение завершает проверку ошибкой и сохраняет кадры.
`VISUAL_THEMES=dark` или `light` позволяет повторить одну тему.

Результат внедрения: все 9 frontend-регрессий, lint и production build прошли.
В тёмной теме прошли 120 сравнений; в светлой — 120 при отдельном повторном
запуске. Первоначальный общий запуск остановился на одиночном расхождении
кадра focus в светлой теме при одинаковых computed styles; повторный прогон
светлой темы прошёл целиком. Суммарно проверены все 240 сочетаний.
