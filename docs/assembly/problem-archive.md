# Этап 9: история и архив проблем

Рабочее окно показывает открытые проблемы. Закрытые доступны отдельно по кнопке «Архив закрытых»: поиск по заказу, SKU и товару, фильтры причины, источника и результата закрытия, серверная пагинация по пять строк. Решённая, но ещё не закрытая проблема остаётся в рабочем окне.

Закрытие включает возврат в сборку и сохранённые исходы завершения, отмены и разбора. Записи не удаляются. Совместимый внутренний снимок сборки сохраняет закрытые записи; обычный список API их исключает, `includeClosed=true` остаётся доступным.

## История

- Просмотр отдельной проблемы получает исходный снимок заказа и причины, исходные отборы и ячейки, связанные проблемы того же заказа и полный поток событий по серверному ordinal.
- Показываются события создания и контекста, проверок остатков, сопоставления SKU, возврата, отборов, ответов Ozon, передачи и завершения разбора из этапов 2–8. Дополнительно доступны связанные журналы проверок, попыток и наблюдений Ozon, сессий и физических возвратов.
- В архиве полный поток раскрыт по умолчанию. Группировка повторов — только представление; события разных складских операций не объединяются. Предыдущие повторы в подсказке идут от старых к новым, задержка скрытия — 500 мс.
- Новые события добавляются; ранее сохранённые payload, идентификаторы и время не переписываются. Запрет UPDATE/DELETE событий сохраняется.
- Для старых сканов без точного времени явно показывается неизвестное время. Время регистрации события не выдаётся за время физического скана. Исходная подпись ячейки берётся из сохранённого контекста, а не из её текущего имени.

## API и безопасность

Новые GET: `/api/assembly/problems/archive` и `/api/assembly/problems/{problemID}/history`. Просмотр не содержит складских команд. Чтение выполняется согласованно в read-only Repeatable Read транзакциях. Новая миграция не требуется; бизнес-правила, резервирование и интерфейс Ozon не менялись.

## Локальные проверки

- `go test ./... -count=1` с PostgreSQL в отдельных временных схемах; `go vet ./...`; сборка API.
- Семь frontend-проверок: создание проблем, история, складская сборка, mapping, Ozon, разбор, архив; oxlint и TypeScript/Vite build.
- Проверены все четыре исхода закрытия, пагинация, фильтры, несколько связанных проблем, сохранность исходных снимков и префикса событий, запрет изменения/удаления истории, повтор без дублей.
- Интеграционная цепочка: сопоставление → проверка остатков → возврат → отбор → отмена → разбор. Истории ранее закрытых причин остались неизменными.
- На рабочем локальном API: health, отдельный архив, рабочий список, полная история существующей проблемы. Снимок сборки и fingerprints остатков и событий до/после совпали. На момент проверки архив пуст, открытых проблем три; демонстрационные закрытия в рабочую БД не добавлялись.

## Ограничения

Точное время старых сканов, ранее не сохранённое, восстановить нельзя. Реальные FBS-вызовы отключены до официального контракта; архив отображает сохранённые проверенные данные адаптера, не выполняет запросы Ozon. Визуальная проверка в браузере и финальная комплексная проверка всей цепочки относятся к следующему согласованному этапу; здесь выполнены компонентные и интеграционные проверки.
