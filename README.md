# TREMOR_SCLAD
Сайт для складского учета. Проект для организации "TREMOR HANDLESS". Все права защищены, сайт не является публичным.

## Проверка приёмки

Из папки `backend` запустите интеграционные тесты в PowerShell:

```powershell
$env:TEST_DATABASE_URL = 'postgres://USER:PASSWORD@127.0.0.1:5432/TEST_DB?sslmode=disable'
go test ./... -count=1 -v
Remove-Item Env:TEST_DATABASE_URL
```

Используйте отдельную тестовую базу PostgreSQL. Пользователь должен иметь право создавать схемы. Каждый тест приёмки создаёт свою схему, применяет миграции 001, 003–005 и 007, добавляет тестовые товары и ячейку и удаляет только свою схему после проверки. Миграция 002 с рабочими начальными данными для тестов не нужна. Без `TEST_DATABASE_URL` интеграционные тесты пропускаются; обычный `go test ./...` не подтверждает поведение базы.

Проверяются сохранение группы товаров и размещений, отмена и повторная отмена, недостаточный остаток для отмены, завершение с неразмещёнными товарами или устаревшим списком размещений, защита завершённой приёмки, два одновременных размещения, безопасное удаление истории, страницы по 5 записей и сортировка по времени в обоих направлениях, включая одинаковые даты и удалённый курсор.

Ручная проверка исправления истории:

1. Завершите приёмку с размещённым товаром.
2. Начните следующую приёмку и разместите в ней товар, оставив её активной.
3. Обновите страницу: активная приёмка должна восстановиться, а завершённые — остаться в отдельном блоке «История приёмок» без ошибки загрузки.
4. Нажмите глаз в строке завершённой приёмки: внутри строки откроются связанные товары с артикулами, ячейки и количества. Повторное нажатие плавно сворачивает содержимое. Номер приёмки — обычный текст. Просмотр истории не меняет активную приёмку.

История загружается по 5 приёмок. Стрелка возле «Завершена» переключает порядок по времени завершения: от новых к старым или наоборот; выбранный порядок запоминается в браузере. При одинаковом времени номер используется только как стабильный дополнительный ключ. Кнопки «Предыдущая» и «Следующая» переключают страницы, круглая стрелка обновления возвращает к первой странице выбранного порядка. Список остаётся видимым во время загрузки, фон страницы не меняется при раскрытии строк. После завершения текущей приёмки список обновляется автоматически. Активные и скрытые сессии не входят в историю, отменённые размещения не входят в её итоги.

Галочка возле обновления открывает подтверждение завершения истории за день. Экспорт в Excel и подготовка истории к следующему дню пока не реализованы: подтверждение не меняет и не удаляет записи.

Удаление завершённой приёмки из истории требует подтверждения. Оно скрывает запись из списка и загрузки последней приёмки, не меняя остатки, размещения и активную сессию. Повторный запрос удаления безопасен. Для этого применяется отдельная миграция `007_receiving_history_deletion.sql`, не зависящая от черновой миграции сборки 006. Исходные записи остаются в базе с отметкой `deleted_at`; вернуть запись можно через базу, отдельной кнопки восстановления пока нет.

Чтобы применить миграцию удаления с теми же настройками подключения, что у API, запустите из `backend`: `go run ./cmd/migrate-receiving-history`. Команда не применяет миграцию сборки 006.
