# TREMOR_SCLAD
Сайт для складского учета. Проект для организации "TREMOR HANDLESS". Все права защищены, сайт не является публичным.

## Проверка приёмки

Из папки `backend` запустите интеграционные тесты в PowerShell:

```powershell
$env:TEST_DATABASE_URL = 'postgres://USER:PASSWORD@127.0.0.1:5432/TEST_DB?sslmode=disable'
go test ./... -count=1 -v
Remove-Item Env:TEST_DATABASE_URL
```

Используйте отдельную тестовую базу PostgreSQL. Пользователь должен иметь право создавать схемы. Каждый тест создаёт свою схему, применяет миграции 001 и 003–005, добавляет тестовые товары и ячейку и удаляет только свою схему после проверки. Миграция 002 с рабочими начальными данными для тестов не нужна. Без `TEST_DATABASE_URL` интеграционные тесты пропускаются; обычный `go test ./...` не подтверждает поведение базы.

Проверяются сохранение группы товаров и размещений, отмена и повторная отмена, недостаточный остаток для отмены, завершение с неразмещёнными товарами или устаревшим списком размещений, защита завершённой приёмки, два одновременных размещения и история при наличии активной сессии.

Ручная проверка исправления истории:

1. Завершите приёмку с размещённым товаром.
2. Начните следующую приёмку и разместите в ней товар, оставив её активной.
3. Обновите страницу: активная приёмка должна восстановиться, а завершённые — остаться в отдельном блоке «История приёмок» без ошибки загрузки.
4. Нажмите номер завершённой приёмки: должны открыться её товары, артикулы, количества, ячейки и даты размещений. Просмотр истории не меняет активную приёмку.

История загружается по 20 приёмок, от новых к старым. Кнопки «Старее» и «Новее» переключают страницы, «Обновить историю» возвращает к последним записям. После завершения текущей приёмки список обновляется автоматически. Активные сессии не входят в историю, отменённые размещения не входят в её итоги.
